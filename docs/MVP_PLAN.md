# MVP implementation plan

## Starting point

SrajMiner is a TypeScript, Vite, and Phaser 3 browser game. `src/main.ts` starts the game, `src/game/MiningScene.ts` coordinates the expedition, and focused modules handle world geometry, saves, campaign progression, trade, structures, and UI. The player can drill, cross a round planet, recover core records, assemble the mothership, travel with core fuel, trade ore, fulfill local orders, and store ore in planet-specific warehouses. Save format 30 retains warehouse capacity upgrades, extractor tiers and fractional production state, adding the expanded ore set and civilian delivery ledger. Browser checks confirm v28 saves migrate without losing stock or structures.

## Main risks

Save migrations must preserve old charts, warehouse stock, and planet-local excavation. Production advances all visited maps over a single capped interval and persists a sub-unit remainder per extractor to prevent repeat-load duplication. Keep balance values in `src/game/config.ts`, use small domain modules, and keep every phase runnable. The manual mining loop remains the acceptance baseline while automation expands it.
